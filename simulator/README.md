# 딸깍 서바이벌 시뮬레이터

브라우저 없이 게임을 돌려 봅니다. **게임 규칙을 베끼지 않고 `../web/src` 를 그대로
불러 씁니다** — 규칙이 두 벌이 되면 여기서 잰 숫자가 실제 게임을 대변하지 못합니다.

```bash
cd simulator
pnpm install

pnpm sim                       # 한 판 돌리고 runs/ 에 기록을 남깁니다
pnpm batch                     # 여러 판 돌리고 분포를 냅니다
pnpm test                      # 결정론·정보 은닉·종료 보장·골든
pnpm typecheck
```

기록을 눈으로 보려면 `viewer/index.html` 을 브라우저로 열고 `runs/` 의 JSON 을
끌어다 놓습니다. 서버도 빌드도 필요 없습니다.

## 무엇을 재는가

- **밸런스 검증** — 수천 판의 생존 일수와 엔딩 분포
- **전략 비교** — 정책을 바꿔 가며 어떤 플레이가 유리한지
- **회귀 테스트** — 고정 시드의 결과가 어긋나면 실패

## 실행 예

```bash
pnpm sim   --seed 1 --policy careful --out runs/run-1.json
pnpm batch                               # 사람 갈래 5종 × 10,000판 (약 24분)
pnpm batch --runs 500 --policy fixer,grinder
pnpm batch --runs 1000000 --policy random   # 무작위 기준선은 판당 0.18ms
```

판당 비용은 정책마다 크게 다릅니다 — 사람 갈래는 약 29ms, `random` 은 0.18ms 입니다.
차이는 스텝 수에서 옵니다. 결정 하나당 1분씩 미므로 판이 길수록 스텝이 늘어납니다.

| 옵션 | 뜻 | 기본 |
| --- | --- | --- |
| `--seed` | 게임 난수 시드. `batch` 에서는 시드 목록을 뽑는 기준값 | `1` |
| `--policy` | 정책 이름. `batch` 는 쉼표로 여러 개 | `survival` / 전부 |
| `--runs` | `batch` 가 돌릴 판 수 | `200` |
| `--tick` | 결정 하나당 흘려보낼 게임 분 | `1` |
| `--max-days` | 이 날을 넘기면 「생존」으로 끊음 | `60` |
| `--sample` | 곡선 표본 간격(게임 분) | `15` |
| `--out` | 기록을 쓸 자리 | `runs/…` |

## 어떻게 도는가

스텝 하나의 순서는 웹과 같습니다.

1. **시간이 흐릅니다** — `session.tick(1)`. 웹에서 캐릭터가 걷고 사람이 고민하는
   동안 매 프레임 도는 시계를, 결정마다 틱 한 번으로 갈음합니다.
2. **화면을 봅니다** — `PlayerView.from(session)`.
3. **누릅니다** — `session.resolveChoice(...)` 또는 `session.performAction(...)`.

무슨 일이 있었는지는 **호출 전후의 상태를 비교해** 알아냅니다. 게임 쪽에 기록용
배선을 새로 달지 않기 위해서입니다.

### 「실제 플레이어처럼」의 경계

정책은 계기판과 시트에 실제로 뜨는 것만 봅니다.

| 보임 | 안 보임 |
| --- | --- |
| 시계, 잔고·체력·크레딧 | 아이디어 도난 확률 |
| 이용자 수·증가율·매출·서버비 | 실패 시 엔딩 확률 |
| 선택지 제목·종류·성공률 %·비용 | 실패 시 새 이슈가 딸려 나올 확률 |
| 이슈 제목과 방치 문구 | **품질**, 누적 매출·지출 |
| | 다음 이슈가 터질 시각, 난수 상태 |

품질이 안 보이는 이유는 계기판에 품질 타일이 없기 때문입니다 — 해결 토스트의
`품질 +N` 으로 증감만 보입니다. `PlayerView` 는 원본 `Issue`·`IssueOption` 을 들고
있지도 않습니다. 참조를 남기면 타입을 우회해 들여다볼 수 있습니다.

### 정책 — 사람은 한 갈래로 고르지 않습니다

화면은 **이슈 목록 → 대응책** 두 장입니다. 「어느 이슈를 볼까」와 「그 이슈를 어떻게
칠까」는 서로 다른 판단인데, 열린 이슈 × 5선택지를 한 줄로 세워 점수 하나로 1등만
뽑으면 그 둘이 뭉개집니다. 그러면 성향을 바꿔도 같은 줄을 누르게 되어 **대안이 생길
자리가 없습니다.**

`HumanPolicy` 는 셋을 나눠 놓았습니다.

1. **두 단계로 나눕니다.** ① 방치 압력을 보고 아픈 이슈를 고르고 ② 그 안에서 값과
   확률을 보고 칠 줄을 고릅니다. 고른 이슈에 마음에 드는 줄이 없으면 목록으로
   돌아가 다른 이슈를 봅니다.
2. **이슈만 보지 않습니다.** 눕기·벌러 나가기도 같은 저울에 올려 함께 겨룹니다.
   사람은 「지금은 이슈 말고 자자」를 늘 저울질합니다.
3. **1등만 고르지 않습니다.** 점수에 온도를 씌워 확률로 뽑습니다(softmax).
   같은 성향도 판마다 다른 길로 갑니다 — 10,000판이 「한 사람의 10,000번」이 아니라
   「여러 사람의 한 번씩」이 됩니다.

절차는 누구나 같고 **저울만 다릅니다.** 그 저울이 `Traits` 입니다.

| 갈래 | 어떻게 치는 사람 | 크게 비튼 축 |
| --- | --- | --- |
| `fixer` | 돈으로 때웁니다. 몸이 아까워 미리 벌어 둡니다 | `moneyWeight` ↓ `staminaWeight` ↑ `earnWeight` ↑ |
| `grinder` | 몸으로 때웁니다. 돈은 못 씁니다 | `moneyWeight` ↑ `staminaWeight` ↓ |
| `clicker` | 딸깍으로 때웁니다. 시간이 아깝습니다 | `creditWeight` ↓ `timeWeight` ↑ |
| `careful` | 돌다리를 두드립니다. 낮은 확률은 안 봅니다 | `riskAversion` ↑ `temperature` ↓ |
| `rusher` | 일단 지릅니다. 자주 흔들립니다 | `riskAversion` ↓ `timeWeight` ↑ `temperature` ↑ |

`riskAversion` 이 가중치가 아니라 **성공률에 씌우는 지수**인 이유는, 확률을 곱으로
키우면 신중한 사람이 오히려 모든 줄을 다 누르게 되기 때문입니다. 지수여야 낮은
확률만 골라 깎입니다.

기준선도 남아 있습니다 — `random`(아무 편도 안 듦), `idle`(손 놓음), 그리고 한 축으로만
고르던 옛 정책 `survival`·`ddalggak`. 기본 배치에는 안 들어가고 `--policy` 로 부릅니다.

정책이 쓰는 난수는 **게임 난수와 갈라 둔 별도 수열**입니다. 같은 것을 나눠 쓰면
정책을 바꾸는 순간 게임 쪽 수열이 밀려, 「정책이 나았다」와 「운이 좋았다」가 섞입니다.

## 결정론

시드가 같고 설정이 같으면 판이 완전히 같습니다. 설정이 결과를 바꾸므로
(`tickMinutes` 가 달라지면 난수를 굴리는 횟수가 달라집니다) 기록에 설정 지문
`configHash` 를 함께 싣습니다.

밸런스를 의도적으로 고쳤다면 골든을 다시 뜹니다.

```bash
UPDATE_GOLDEN=1 pnpm test
```

`test/golden.json` 의 diff 가 곧 변경의 크기입니다. **눈으로 읽고** 커밋합니다.

## web 과의 접점

시뮬레이터를 위해 `web` 에서 연 것은 [`web/src/core/Session.ts`](../web/src/core/Session.ts)
네 가지뿐입니다.

- 생성자가 `seed` 를 받습니다 (기본값은 전과 같은 `1`)
- `resolveChoice` 가 public 이고 결과를 돌려줍니다 — 헤드리스에서는 캐릭터를
  책상까지 걷게 할 수 없어 여기로 바로 들어옵니다
- `performAction` 이 결과를 돌려줍니다
- `ended` · `result` 접근자

세션 클래스는 여전히 `Session` 하나입니다.
